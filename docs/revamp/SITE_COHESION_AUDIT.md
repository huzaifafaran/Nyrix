## Route-family coverage and remaining visual gate

Static route tree covers `/`, `/company`, `/company/team`, `/company/advisors`, `/solutions`, four service detail URLs, `/products`, `/products/:slug`, `/case-studies`, two case detail URLs, `/resources`, `/resources/articles`, `/resources/podcasts`, `/contact`, `/agents`, `/privacy-policy`, and `*` 404 (`src/App.js:103-180`). Source review confirms common header/footer shell and shared IBM Plex/Inter tokens, with the exceptions above. It **does not** confirm every route visually. The lead should load each representative route directly and through navigation, then inspect 320, 375, 414, 768 and desktop widths for cut-off text/media, button shape, typography, balanced spaces and footer density. Explicitly test contact labels/focus, mobile menu, reduced motion, intro heading emphasis and the full directory on a deep route. The browser gate previously denied localhost access to this agent; screenshots from a permitted reviewer are needed for honest sign-off.

## Fast integration order

1. Fix product CTA radius and privacy visual island; keep policy copy/date separate for approval.
2. Centralize a `heading-emphasis` visual rule and configure one word per route family; preserve accessible heading text.
3. Remove purple **text** overrides selector by selector; keep accent underlines/borders/media.
4. Normalize product showcase grid/palette and shorten footer invitation without losing directory content.
5. Compare direct route screenshots at required widths; only then call the site picture-perfect.
